## 六、测试数据清理

主集合执行完成后，先验证以下删除与引用保护行为：

| 编号 | 用例 | 预期结果 |
|---|---|---|
| CLN-001 | 删除测试收藏 | 删除成功 |
| CLN-002 | 删除测试评论 | 删除成功 |
| CLN-003 | 删除存在借阅历史的测试图书 | HTTP 409 或业务错误，引用保护生效 |
| CLN-004 | 删除仍包含图书的测试分类 | 业务码非 0，分类保护生效 |

系统没有提供删除历史借阅记录的公开接口。完整业务闭环执行后，如需恢复数据库整洁度，应仅在测试环境中按本轮生成的精确 ID 使用事务清理，并在提交后复核各关联表数量。一次性清理 Collection 不纳入版本控制，避免提交失效 ID。

## 七、判定标准

- 主集合所有 Postman 断言通过，核心业务闭环视为通过。
- 401、403、400 等负向用例按预期返回时视为通过。
- 清理步骤用于删除可直接删除的数据并验证引用保护；数据库最终恢复结果单独记录，不影响主测试通过率。
